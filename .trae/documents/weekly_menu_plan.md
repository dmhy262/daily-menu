# 每周菜谱自动生成器 - 功能设计方案

## 一、需求分析

### 1. 核心需求
用户需要一个每周菜谱自动生成器，具备以下核心功能：
- **批量导入菜的名称**：支持快速批量添加菜谱名称，自动调用大模型生成完整菜谱
- **拉黑指定的菜**：排除不喜欢或不适合的菜品
- **生成每日菜单**：点击按钮生成每天的午餐和晚餐菜单
- **自定义用餐人数**：可设置每顿的成人数和儿童数
- **智能数量匹配**：根据人数生成适合数量的菜品

### 2. 现有功能（项目已有）
- 单个菜谱添加
- 菜谱拉黑/取消拉黑
- 周菜单生成（早/午/晚三餐）
- 购物清单
- 菜谱详情查看
- 数据本地存储（localStorage）

### 3. 待新增/增强功能
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 批量导入菜谱 | 仅需提供菜名，自动调用大模型生成完整菜谱 | 高 |
| 用餐人数配置 | 可设置每顿的成人数和儿童数 | 高 |
| 智能菜单生成 | 根据人数生成适合数量的菜品（仅午/晚餐） | 高 |
| 仅午/晚餐模式 | 用户只需要午餐和晚餐菜单 | 高 |

## 二、功能设计

### 模块一：批量菜谱导入（核心增强）

**功能描述**：用户仅需提供菜品名称列表，系统自动调用大模型生成完整的菜谱信息（原料、步骤、时间等）

**设计方案**：
- 提供文本输入框，用户可粘贴多个菜名（每行一个）
- 支持选择适用时段（午餐/晚餐/通用）
- 点击导入后，逐个调用大模型API生成完整菜谱
- 显示导入进度和结果反馈
- 支持导入失败重试

**界面设计**：
- 在「菜谱管理」页面添加「批量导入」按钮
- 弹窗形式展示批量导入界面
- 包含导入说明、示例和进度显示

**技术实现要点**：
```
输入：菜名列表（如：["宫保鸡丁", "鱼香肉丝", "糖醋排骨"]）
输出：完整菜谱列表（包含原料、步骤、时间、难度等）

流程：
1. 用户输入/粘贴菜名列表
2. 选择适用时段
3. 点击"批量导入"
4. 循环调用大模型API生成菜谱
5. 显示导入进度（成功/失败数量）
6. 保存到本地菜谱库
```

---

### 模块二：用餐人数配置

**功能描述**：允许用户自定义每餐的成人数和儿童数，用于智能生成合适份量的菜单

**设计方案**：
- 提供配置面板，可设置：
  - 成人数量（默认1-10人，可自定义）
  - 儿童数量（默认0-5人，可自定义）
- 配置为全局设置，应用于所有餐次
- 配置数据持久化存储（localStorage）

**界面设计**：
- 在周菜谱页面顶部添加人数配置区域
- 使用数字输入框或加减按钮调整人数
- 实时显示当前配置的总人数

---

### 模块三：智能菜单生成（核心功能）

**功能描述**：根据用餐人数智能生成适合数量的午/晚餐菜单

**设计方案**：
- 基于人数计算每餐应生成的菜品数量：
  - 成人：每餐1个主菜 + 1个配菜
  - 儿童：每餐1个主菜（简单、清淡菜品优先）
  - 可配置每餐菜品数量上限
- 算法逻辑：
  - 根据人数确定每餐的菜品数量
  - 从可用菜谱中按类型(午餐/晚餐)筛选
  - 随机选择但确保一周内菜品多样性
  - 自动排除拉黑的菜品

**实现逻辑**：
```
输入：成人数量(A)、儿童数量(C)、可用菜谱列表
输出：一周每日菜单(午餐、晚餐)

算法：
1. 计算每餐菜品数量 = A + C（或按配置）
2. 从菜谱库筛选可用菜品（排除拉黑，按午/晚餐分类）
3. 随机选择菜品，确保一周内不重复
4. 按天和餐次组织返回结果
```

---

### 模块四：拉黑管理

**功能描述**：管理不喜欢或不适合的菜品，支持单个和批量操作

**设计方案**：
- 支持在菜谱列表中单个拉黑/取消拉黑
- 支持批量勾选拉黑
- 拉黑的菜品在菜单生成时自动排除
- 提供拉黑列表查看和管理

**界面设计**：
- 菜谱列表中显示拉黑状态标识
- 支持一键取消拉黑
- 周菜单中可直接拉黑当前显示的菜品

### 2. 菜谱管理页面
- **导入区域**：
  - 批量导入按钮
  - 批量导入弹窗

  - 显示所有菜谱（名称、类型、难度、时间）
  - 支持搜索和筛选
  - 支持单个编辑、删除、拉黑

## 四、数据结构

```json
{
  "id": 1,
  "name": "番茄炒蛋",
  "type": "lunch",           // lunch/dinner/all
  "ingredients": ["番茄 2个", "鸡蛋 3个", "盐 1勺", "糖 半勺"],
  "steps": ["番茄切块，鸡蛋打散", "热锅倒油，倒入蛋液炒至凝固盛出"],

  "calories": 350,
  "difficulty": "简单",      // 简单/中等/困难
  "isAI": true               // 是否由AI生成

```

```json
  "adults": 2,               // 成人数量

```

## 六、API接口设计（大模型调用）

### 生成菜谱接口
- **Endpoint**：`/api/recipe/generate`
- **Method**：POST
- **请求体**：
```json
{
  "name": "宫保鸡丁",
  "type": "lunch"
}
```
- **响应体**：
```json
{
  "success": true,
  "data": {
    "name": "宫保鸡丁",

  }

```

## 十、风险评估

| 风险点 | 描述 | 应对方案 |
|--------|------|----------|
| API调用失败 | 大模型API可能超时或失败 | 添加重试机制和错误提示 |
| API调用成本 | 批量导入可能产生较多API调用 | 限制单次导入数量，添加调用确认 |
| 数据一致性 | AI生成的菜谱格式可能不一致 | 统一数据格式化处理 |
| 存储容量 | localStorage容量限制 | 提示数据清理，支持数据导出 |

## 十一、总结

本方案基于现有React项目，核心增强以下功能：

1. **批量菜谱导入** - 仅需提供菜名，自动调用大模型生成完整菜谱
2. **用餐人数配置** - 灵活设置成人/儿童数量
3. **智能菜单生成** - 根据人数生成适合数量的午/晚餐
4. **拉黑管理** - 高效管理不喜欢的菜品

通过这些功能，用户可以更便捷地管理菜谱，并根据家庭人数智能生成每周菜单。
